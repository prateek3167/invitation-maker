# Account security operations

Email/password accounts now require verified email. Signup creates no session; the first valid verification creates one. Links expire after one hour and replay cannot create another session. Resend is rate limited. Recovery returns the same generic response for existing/unknown addresses; 30-minute, one-use password resets revoke all sessions. Password changes require the current password and revoke other sessions.

Local development writes private JSON messages to ignored `.data/mailbox`; run `npm run mail:preview -- person@example.test`. No mailbox HTTP route exists. These messages are not delivered externally. Set `SMTP_URL` and `MAIL_FROM` for TLS-required SMTP delivery. Public email/password capability is disabled unless both are present. Real provider delivery, DNS reputation and inbox verification remain a staging gate.

Account & security offers name editing, authenticator enrollment/verification, one-use backup codes, password changes, safe device listing/revocation, streamed NDJSON data download and permanent account deletion. Deletion cascades projects/cards/auth records; browser drafts and previously downloaded files remain independent. Download excludes password hashes, provider credentials, session/reset tokens and authenticator secrets. Account exports are personal data: keep them private.

To provision an administrator, the intended user first verifies email and enables an authenticator. Stop a local embedded server before using its database from the CLI, then run `npm run admin:promote -- person@example.test`. The command requires those conditions, grants the role transactionally and revokes every prior session. The user must sign in with MFA. No HTTP role-promotion endpoint exists; role and MFA flags cannot be edited through profile input. Administrators cannot disable MFA through the application. Recovery requires server-operator identity verification; never promote an unverified account or silently bypass MFA.

Migration `0002_account_security.sql` adds role/MFA fields and encrypted-library-managed authenticator storage without rewriting existing account/project data. Existing unverified accounts must verify before opening projects. Back up before migrations. Roll back application traffic first; retain additive columns/tables and the same managed auth secret. Never edit applied migration history. Restore the complete pre-migration backup only with a planned outage and explicit acknowledgement that subsequent writes would be lost.

Validation: 23 unit/integration tests pass (one external PostgreSQL test skipped), existing five Chrome regression tests pass, and a sixth Chrome flow passes verified signup, profile editing, axe checks, safe session listing/revocation, data download, recovery/login and account deletion. Integration tests exercise verification replay, forbidden elevation, expired/reused reset tokens, session revocation, MFA challenge/backup-code reuse and secure promotion. SMTP/OAuth and real network PostgreSQL remain unverified locally.

Auth rate limiting currently uses a conservative shared per-path bucket because no client IP header is trusted by default. Configure and verify a trusted edge/proxy identity before public rollout; never trust arbitrary forwarded headers. This remains a public scaling/configuration gate.
