# Private media and export operations

Local defaults: `.data/media` and `.data/exports`, both ignored and outside public/. Public mode requires absolute durable `PRIVATE_MEDIA_DIRECTORY` and `PRIVATE_EXPORT_DIRECTORY` configuration. The web server and worker need matching mounts and restricted filesystem identities; use encrypted disks and provider backups. No public file server or anonymous asset route is configured.

The account editor validates processed photos again on the server before persistence, shows normalized bytes after save, and preserves crop controls. API clients receive portable embedded photos only after ownership checks. New stored documents use `asset:UUID`. Legacy inline documents remain compatible. The owner-only asset URL is `/api/v1/assets/:id`; it checks the session, verified email and ownership and sends private/no-store. Photo limits are 6 MB input, 40 megapixels, two concurrent decoders/process, ten processing seconds, 2,000-pixel derivatives, 200 photos and 100 MB/account. Browser uploads first shrink originals up to 12 MB. The backend checks actual bytes regardless of the MIME label.

For an account invitation, open Download → Queue background export, then Export history. A job binds its request key to invitation ID/revision/format; reusing it with a different request is rejected. Ownership and expiry apply to status/history/download. Browser PNG/JPG/PDF downloads remain available independently. If rendering fails, jobs retry up to three times; editing the invitation does not change a captured job. Create a new request to capture a newer revision.

Local worker startup is triggered by authenticated export submission/status/history requests and drains available jobs in one process. After a local server restart, opening Export history resumes queued or expired-lease work. Production must run `npm run worker:exports` as a supervised process against DATABASE_URL. That command rejects embedded storage. Install a controlled Chrome browser and its fonts/libraries, optionally configure EXPORT_BROWSER_EXECUTABLE or EXPORT_BROWSER_CHANNEL, and keep sandbox/resource limits and network restrictions enabled. Provisioning/installing a production browser was not performed here.

`npm run storage:maintain` previews expired-job/orphan-file cleanup. Run with `-- --apply` to apply it. Local embedded operation requires stopping the web server and adding `--offline`; never run two processes against the same PGlite data directory. Production schedules it against the shared PostgreSQL/mounts. Only recognized, unreferenced managed filenames older than 24 hours are removed; new/unknown/live files remain. Expired job records are removed. User-requested Remove unused account photos deletes only assets not referenced by an invitation. Export snapshots already embed their images.

Account deletion removes managed photos/artifacts and auth/project records. An interrupted delete/write can leave an unreferenced file for maintenance to remove after the 24-hour grace period. Backup retention is separate and must be agreed for the deployment/market. Mailbox captures contain verification/reset links; keep them private and apply an operator retention policy. Do not expose `.data`, mounts, backups, traces or mailbox messages through hosting.

Monitor `api.request` status/duration and request IDs plus `export.completed`, `export.render_failed`, `export.lease_lost` and `export.worker_failed`. Invitation text, image bytes, email/reset tokens and credentials are excluded from these application events. Configure alerts for queue age, terminal failures, expired leases, storage usage, delivery failures and database availability in the real hosting environment; no external monitoring service is claimed connected.

Research: decoding limits follow [Sharp constructor documentation](https://sharp.pixelplumbing.com/api-constructor/); worker network isolation follows [Playwright context/service-worker documentation](https://playwright.dev/docs/api/class-browsercontext). Architecture details and limitations are in [ADR 0002](../decisions/0002-private-media-and-durable-exports.md).
