# ADR 0002 — Private media, export leases and immutable templates

Status: implemented local foundation, 2026-11-13. Public hosting/storage/font decisions remain launch gates.

Account image input is decoded on the server with Sharp under byte, pixel, format, concurrency and time limits. Only JPEG/PNG/WebP signatures are accepted; animations and corrupt images are rejected. Orientation is applied, dimensions bounded to 2,000 pixels, transparency flattened and metadata stripped. Owner-scoped content/source hashes avoid repeated JPEG recompression and duplicate storage. Quotas are serialized per account (200 photos / 100 MB).

Private JPEG derivatives live outside public/ under `.data/media` locally or an explicitly configured durable private mount. Database documents reference `asset:UUID`; authorized API responses resolve these to embedded data for portable previews/downloads. Legacy embedded photos remain readable and move to managed storage when next saved. A database trigger/FK enforces asset ownership and prevents deleting referenced photos. Account controls can delete unused photos; deletion of an account removes its managed files. This is an interim filesystem adapter, not a verified S3 implementation. Web and worker instances require the same mounted private storage; ordinary ephemeral/serverless disks are unsuitable. Final managed object storage or shared mount selection needs the actual deployment environment.

PostgreSQL stores durable export jobs with saved revision, embedded SVG snapshot/hash, renderer identifier, template fingerprint, owner, idempotency key, format, attempts, lease and expiry. Jobs capture all image bytes. Later invitation edits, template publication and unused-photo cleanup cannot change a captured export. At most 50 non-expired jobs/account; download authorization expires after seven days. GET status/history queries omit private SVG payloads.

Workers claim rows with FOR UPDATE SKIP LOCKED, use a two-minute lease, retry up to three times and reject stale completion. Lease-specific artifact names prevent a stale worker overwriting another attempt. A network-isolated headless Chrome rasterizes the canonical SVG through the same image/canvas path as browser downloads; PDF is the same raster RGB image in jsPDF. Production uses a separate PostgreSQL worker; single-process embedded development uses one in-process worker. The installed Chrome/font environment must be controlled and staged. Pixel identity was proven locally; fonts are still the existing Georgia/Arial fallback stacks, so cross-platform font equivalence and licensing/pinning are unresolved release work.

Administrator-only immutable template versions use validated JSON from supported compositions, a provenance/rights note, canonical fingerprints and an explicit publication pointer. New invitations pin a template snapshot; replacing/withdrawing publication preserves saved invitations and exports. Editing an existing snapshot is forbidden. Definitions cannot contain executable SVG/HTML or arbitrary asset URLs. This provides publishing operations, not proof that all 50 existing concept variants are distinct, commercially cleared artwork.

Migrations 0002–0006 are additive and checksummed. Do not roll back to an old application that cannot resolve asset references or template snapshots. Retain a compatible application during rollback, or stage an explicit conversion/recovery procedure; never delete new columns/tables or restore over newer user writes automatically.
