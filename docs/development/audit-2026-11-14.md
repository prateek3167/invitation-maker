# Whole-project audit and regression record — 14 November 2026

## Assessment and scope

The local create/save/preview/export application is implemented, but the complete planned product is **not production-ready**. Public invitation publishing, remote guest RSVP delivery and billing are absent. Production fonts, external services, operational recovery/load checks and human acceptance remain release gates. A passing local suite does not close those gates.

The user explicitly requested local work without hosting or external database setup. No hosting, paid service, external database, deployment or production account setting was configured. Findings are persisted in this report and root MEMORY.md; this is repository-local memory.

This audit inventories maintained files and assets, reviews source/configuration/dependency boundaries and executes the application against isolated fixtures. Generated dependencies, build outputs and database binary pages are classified by purpose, rather than treated as source requiring manual line-by-line review. No claim of exhaustive security certification, every possible input, cross-browser conformance or production performance is made.

## Production-readiness gates and next phases

Proceed sequentially; each increment needs tests, current docs and an explicit release boundary.

1. **Complete advanced-editor acceptance.** Close any remaining audit regressions; bundle reviewed fonts; verify exact visual/worker parity across Hindi, photo/non-photo, formats and multi-card suite exports. Add real-browser/keyboard/touch UAT and performance budgets. Deliver a lossless editor with reproducible acceptance artifacts. Depends on asset/font decisions, not paid hosting.
2. **Implement real publication and RSVP.** Owner-authorized explicit publish, opaque unguessable tokens stored hashed, immutable public snapshots, expiry/revocation, private asset policy, no guest-list leakage and server-backed validated responses. Add idempotency, abuse limits, deadline/party/ceremony settings, retention/deletion/export and host notification policy. Test two clean browser contexts, foreign owners, expired/revoked links and concurrent/repeated submissions. Current device preview is not a substitute.
3. **Finish local release hardening.** Validate additive migration upgrades with representative saved documents, normalize catalog/document size budgets, lazy-load heavy editor/PDF tools where measured useful, strengthen script CSP with a compatible nonce strategy, add error/latency dashboards and complete artwork/privacy/support reviews. Test offline/error/quota cases and supported browsers. No automatic bulk dependency upgrades are justified by a zero-vulnerability scan.
4. **Validate deployed operations only when requested.** Use separately authorized hosting/database/storage/SMTP/OAuth, trusted proxy, controlled browser/font environment, restore exercise, load test and staging smoke tests. Record actual service behavior, rollback, RPO/RTO and alerts. This phase is excluded by the user's present local-only instruction.
5. **Billing and later roadmap.** Requires actual pricing/provider/business decisions before checkout, entitlements and signed idempotent webhook/reconciliation implementation. AI services, collaboration, marketplace, additional languages and video remain distinct optional roadmap work, not completed features.
